# tsstore

嵌入式时间序列存储库（Go），无外部数据库进程。每条序列由字符串 `series` 标识，观测点以 `int64` 时间戳和 `float64` 值表示。

## 能力

- `Append`：写入新观测；同一时间戳已存在时返回 `ErrAlreadyExists`。
- `Revise`：迟到修订；时间戳不存在时返回 `ErrNotFound`，否则写入一个更高版本。
- `Range(series, start, end)`：半开区间 `[start, end)` 范围查询，结果按时间戳排序。乱序写入不会影响边界判定。
- `Snapshot`：获取某一全局版本的一致性只读视图；在后续写入、过期、刷盘与压缩期间，在途读取始终看到同一版本。
- `ExpireBefore(series, t)`：为 `ts < t` 的存活点写入持久化墓碑（tombstone）。
- `Flush`：把内存表刷成不可变的有序分段文件。
- `Compact`：合并分段，物理清除已过期数据与无用历史版本。
- `Bounds`：返回序列当前（或快照内）存活数据的时间边界与版本。

## 持久化与崩溃恢复

数据目录包含：

- `wal.log`：仅追加的预写日志，每条记录带长度与 CRC32，尾部撕裂记录会被忽略；每次确认写入都 `fsync`。
- `seg-NNNNNNNNNN.seg`：不可变有序分段，带魔数、版本号与 CRC32。
- `manifest.json`：原子重命名写入，记录当前分段集合、下一个分段 ID 与最大版本号。

刷盘在分段文件落盘并 fsync、manifest 提交后才轮转 WAL。压缩先把活动内存表刷为一个“未提交”输入段但**不**轮转 WAL：

- 压缩在 manifest 提交前崩溃：未提交的输出段与活动段都不被 manifest 承认，重启时清理孤立文件并重放 WAL，已确认写入不丢。
- 压缩提交后：旧分段可立即删除；仍打开的快照持有内存中的旧分段指针，在途读取不受影响。

历史版本裁剪以最老存活快照版本为界：该版本及更新的版本全部保留，更早的版本只保留最新一个（若为删除则丢弃）。

## 运行测试

```
go test ./...
go test -race ./...
```

测试覆盖追加/修订一致性、乱序边界、快照与压缩并发、过期物理回收、无 Close 的硬重启恢复、用直接排序参考数据核对跨段查询，以及压缩中断后的恢复与再压缩。
